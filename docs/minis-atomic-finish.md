# Minis owner-bound atomic finish

Based on native14 60e42df. Codex continues using automation_native_end; that does not stop the service. Only the explicitly requested Minis cleanup calls automation_native_finish.

Request: lease_id, completion_policy (return_chat / stay / skip_unknown), stop_service:true, and origin_session_id only for return_chat. The origin must come from the current trusted Minis task context, not a guessed/latest chat. The native route is fixed to minis://sessions/<opaque ASCII id>; arbitrary URLs, paths, query strings and other apps are rejected. The local audited Minis DeepLinkRouter supports this canonical route, but source support does not prove the installed app navigated successfully.

The process-local session model checks current stored owner and id, including an expired or already ended lease. A lease replaced by another owner/id cannot stop that newer task. On first finish it marks the stored lease ended and permanently closes admission for this server object. Identical duplicate requests return the same logical ended state without repeating return or stop; changed policy/origin is rejected. Ordinary End remains unchanged and permits another lease.

Before acknowledging, the server synchronously revokes service F13 authorization. New native/legacy Begin and mutating UI/config are refused while closing. Previously queued config stop/rebind closures check the captured server identity and closing state. End then stop is therefore not two client RPCs with a foreign-owner window.

The encrypted reply has normal native/mode/lease_id/state:ended/deadline fields plus service_finish:closing, completion_policy, return_route:dispatched/skipped_stay/skipped_unknown/unavailable and chat_verified:false. Dispatched means a one-shot local cleanup was scheduled, not proof of openURL acceptance or visible chat. No receipt claims Automation Running disappeared. A lost reply must not trigger fresh input, another Begin or a config-stop fallback.

Transport contentProcessed or an independent 0.5-second fallback starts the same one-shot Runner cleanup. The callback uses the serial RPC lane, checks the exact current server and a two-second dispatch budget, and opens the fixed Minis route via UIApplication only for return_chat. stay and skip_unknown do not change the foreground. The callback and an independent three-second fallback both call the official stop on the captured server instance, with one-shot suppression. No process killing, pairing changes, clipboard operations, Focus or Auto-Lock changes occur. Caller suspension after returning to Minis cannot lose the scheduled stop.

The listener fallback can run while the UI queue is blocked; XCTest teardown and visible Automation Running disappearance may still await the main thread. A private event already admitted just before closing can race with revocation. This is not a hard real-time guarantee. UIKit open completion is logged only as URL accepted/failed, never chat verified. Unknown task input outcomes should select skip_unknown and still stop, rather than adding navigation or replaying input. The client must stop new work, preserve unknown outcomes, and report cleanup acceptance separately from actual UI confirmation.

Foundation tests cover closure of future Begin, duplicate matching/mismatch, foreign owner and stale id, expired cleanup without a new UI lease, route constraints and no-route policies, and unchanged Codex End. Windows source checks and git diff --check are the only checks run in this implementation lane; Swift/Objective-C compilation, transport delivery timing, installed Minis navigation and visible service shutdown require integration CI/device verification.


Explicit manual takeover is different from passive expiry or lock/health failure. The authenticated manual takeover route sets a process-local tombstone on the old task. Its subsequent atomic finish is refused before ending/sealing the service, even if no replacement native lease has begun. A new permitted Begin resets the per-task tombstone, while the stored id/owner still prevents the old task from stopping it. Ordinary TTL/heartbeat expiry and lock/health revocation retain only that same stored owner's cleanup authority; they never grant new UI permission. Tests distinguish explicit takeover from those passive failures. Crashes, suspension, unreachable transport and replies lost after acceptance remain unconfirmed boundaries; independent five-second cleanup budget means a request may be sent after local expiry, not that every expired task is guaranteed to stop the service.
